## Which versions

CycloneDX 1.6 is final (ECMA-424, first edition).

SPDX 3.0 has no hardware profile. The Hardware and SupplyChain profiles arrive in SPDX 3.1, whose first release candidate was published on 2026-01-26 and which was still a release candidate on 2026-09-20: [spdx-spec releases](https://github.com/spdx/spdx-spec/releases) and [spdx-3-model releases](https://github.com/spdx/spdx-3-model/releases) list `3.1-rc1` as a pre-release and no 3.1 final. The rendering therefore targets 3.1-RC1 and says so: its `@context` is the RC1 context, `specVersion` is `3.1.0-rc1`, and the HBOM lists it as format `SPDX-3.1-RC1`. When 3.1 is final, the renderer moves to the final schema and the format `SPDX-3.1`, and this table is updated.

Two details of the RC1 schema:

1. The RC1 model's own built-in elements write `specVersion` as `3.1`, which the schema's semantic-version pattern rejects. The renderer writes `3.1.0-rc1`, which the pattern accepts.
2. The schema's IRI pattern `^(?!_:).+:.+` uses a lookahead, which Go's RE2 does not support. The tool checks that one pattern as written (does not start with `_:`, then `.+:.+`) and compiles every other pattern with Go's regexp package; see `tools/hslsa/render.go`.

The JSON Schema checks structure only. The SPDX model also ships SHACL shapes, which check more (for example the class of each relationship end); the renderer is not checked against them yet.
